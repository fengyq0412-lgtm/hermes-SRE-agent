# Hermes SRE Agent

面向 AI 与 Web 服务的、**证据优先、审批受控**的 SRE 智能体。

```text
观察 → 诊断 → 制定计划 → 人工审批 → 修复 → 验证
```

Hermes 的目标不是抢先猜出答案，而是把每条结论和真实采集结果关联起来；任何会改变状态的操作，都不能绕过人工审批。本仓库目前包含一条完整、可复现的慢接口故障诊断链路，也能安全读取本机的只读状态，适合作为可演示、可审查的作品集项目。

## 一分钟演示

```bash
# 使用 Conda 建立环境（首次执行）
conda env create -f environment.yml
conda activate hermes-sre-agent

# requirements.txt 会以可编辑模式安装本项目，获得 hermes 命令
pip install -r requirements.txt

# 无需模型密钥的确定性演示
hermes "legal-agent 最近很慢，帮我排查原因" --mode rules --scenario api_slow
```

## Agent 模式：像 Codex 一样从终端自然语言开始

Hermes 默认进入 Agent 模式。你只需启动终端并描述问题；模型会在只读工具白名单中自主选择健康检查、日志、Docker、GPU、Git 变更或代码差异审查工具。模型不能获得任意 Shell、写文件、重启服务或删除资源的权限。

Hermes 使用 OpenAI Chat Completions 兼容协议，因此可以对接任意提供该协议的国内或本地模型服务。将模板复制为根目录 `.env`，然后填写供应商地址、密钥和模型名：

```bash
cp .env.example .env
# 编辑 .env 后，Hermes 会在启动时自动读取它

# 单次自然语言诊断
hermes "昨天部署后 legal-agent 接口从 800ms 变成 4 秒，帮我排查"

# 连续对话式终端
hermes --interactive
```

连接本地兼容服务时，可使用 `http://localhost:端口/v1` 或 `http://127.0.0.1:端口/v1`。远程模型地址必须使用 HTTPS，避免 API 密钥以明文传输。

## 本地控制台：项目选择、代码审查与修复

Hermes 提供本地项目 Agent：在页面选择项目文件夹，输入「帮我检查这个项目有哪些 bug」或「修复 main.py 的边界错误」，Agent 会自动选择审查或修复流程。可以继续追问，例如「第二个问题在什么条件下触发？」。需要将修复写回项目时会弹出审批请求；批准后当前任务继续执行。

任务会按本次要求区分完成条件，页面显示所选模式：

| 你的要求 | 行为与完成条件 |
| --- | --- |
| 「检查有哪些 bug」「怎么修复」「只给建议，不要改代码」 | 只读分析，读取证据后给出解释或建议，不产生修改审批 |
| 「请修复这个 bug」「修改 main.py」「就按上面的方案改」 | 执行修改，必须在临时副本形成实际补丁，再验证并请求人工审批 |
| 修改请求无法执行，或模型一直只给文字建议 | 显示「修改任务未完成」和阻碍，可继续追问；不会冒充已完成 |

执行修改时，系统会检查实际文件净变更；空替换、改完又改回、只输出代码块均不能满足完成条件。模型提前结束且没有补丁时，最多纠正两次，要求继续调用编辑工具。工具预算仍有限，不会无限循环。缺少明确目标、不支持的文件类型或无需合理修改时，应说明依据，不能为满足补丁条件制造无关改动。意图分类格式异常且无法确定修改授权时默认只读，用户可继续明确要求修改。

模型报告受阻时，编排器会进行一次复核，要求核对当前代码、身份来源、相关实现及历史约定；预算紧张时至多追加四次工具调用。找不到现成的校验函数不等于不能开发：用户已明确规则时，可在已有 Python 业务文件中新增函数并接入调用。权限主体、资源归属或放行规则确实没有定义时，Agent 应返回一到三个具体澄清问题，页面显示「需要确认业务规则」；直接在当前会话回答即可继续。Hermes 不应自行猜测权限规则，也不会把恒真校验当作完成。工具能力限制仍会明确报告为未完成。

源码查询提供 `search_code({text})` 跨文件字面搜索，以及 `resolve_symbol({name})` 静态定位 Python 定义和 `from ... import ... as ...` 别名。模型把“没搜到同名定义”当成“函数不存在”并准备询问用户时，程序会先核对别名及目标模块定义；若能定位，会将文件、行号和必要源码片段交还模型继续处理。静态定位不执行项目代码；动态导入和生成的符号仍可能无法解析，未匹配不等于已证明不存在。

取证预算耗尽但尚无修改时，会进入独立的补丁生成阶段，最多调用模型三次。此阶段不再执行浏览工具，要求基于已读取源码提交 `patch` JSON，包含 `changes` 精确替换列表和修改说明；最多 12 处替换、5 个已有业务文件。整批替换失败会恢复临时副本，再要求模型纠正。成功生成净变更后照常运行沙箱、展示 diff 并等待人工审批；没有有证据的可修复问题时仍应明确说明，不为产生补丁而制造无关改动。

```bash
# 从 Hermes 项目目录启动
hermes-web
```

## 多轮对话与记忆

每个项目可以有多个独立会话。后台根据会话标识读取历史，不接受页面伪造的聊天内容。原始问题、回答、执行状态、用量、diff 和测试结果持久化到本地 SQLite；源码读取结果不整段重复存储，只保留文件与行号索引。刷新恢复正在进行的任务；服务重启后中断任务会明确显示中断，待审批补丁失效，需重新生成并验证，不能恢复旧写回权限。

默认上下文由最近 **3 轮问答**、更早历史的**增量摘要**和近期**工具证据索引**组成，总历史内容限制为 **24000 字符**。窗口滑动时只压缩刚移出的轮次并更新旧摘要，摘要调用的 token 也计入本轮用量。摘要失败会退回原文摘录，长消息按预算缩略，完整记录仍保存在会话库中。意图判断与执行 Agent 使用同一份历史，避免分类器只记得上一句话。

Agent 可调用 `search_history({text})` 检索当前会话的原始用户要求和助手回复，找回摘要遗漏的细节。工具索引只帮助定位，历史模型建议不等同于真实代码现状；生成补丁前仍须读取当前源码。摘要有损，无法保证无限保留每个细节；项目之间、同一项目的不同会话之间不自动共享记忆。

每条回答的「本轮上下文」可查看实际带入的近期轮数、已压缩轮数、字符数和摘要；运行日志同时记录 `context_prepared`。`.env` 可设置 `HERMES_CONTEXT_RECENT_TURNS`（1–10，默认 3）与 `HERMES_CONTEXT_MAX_CHARS`（8000–64000，默认 24000）。这是历史上下文的字符预算，不含系统提示、本轮提问和本轮工具输出，也不是供应商的 token 计费。

会话库位于 Git 已忽略的 `.hermes/` 中，文件默认仅本机用户可读写。由于要恢复原始问答及 diff，库中可能包含用户主动输入或模型回答中的敏感内容，请按项目数据管理。此功能启用前未保存的旧会话无法由摘要日志完整还原。

服务只监听本机回环地址，并验证页面会话令牌。密钥仅在 Python 服务端使用；`.env` 已被 Git 忽略。**点击发送会将相关源码片段发送至你在 `.env` 配置的模型服务**；工具默认排除隐藏文件、`.env`、凭据文件、依赖目录、生成文件和符号链接，但不等同于完整的源码秘密检测。

源码审查单次最多调用 10 次工具，之后预留两次模型调用生成最终报告；最多列出 500 个文件，每次最多读取 200 行，超出范围会提示截断。报告要求给出总体风险等级、已确认问题、待验证风险和审查范围。没有确凿缺陷时仍会说明残余风险，但不会把猜测写成已确认 Bug。若模型两次都不输出结论，页面仍会展示已读取范围和“待评估”的保底报告。回答基于实际读取范围，不代表已覆盖整个项目；只有启用沙箱且工具实际执行后才有测试结果。页面显示简化后的检查进度，最终回答在模型返回后展示，暂非逐 token 输出。

修改任务在取证预算结束后使用独立的补丁提示和已读取的源码片段，不再重复带入整段工具对话；补丁阶段最多允许两次定点补读。模型默认最多输出 4096 token，可在 `.env` 用 `HERMES_MAX_OUTPUT_TOKENS` 设置为 256–16384。若服务商不支持较高上限，仍可能截断；此时日志会记录 `output_truncated`。补丁支持精确文本替换，或仅在模型实际读取的当前版本行号范围内替换整行；同一批次同一文件最多使用一次行号替换。新文件用完整内容生成，支持业务代码和测试。所有改动只进入临时副本，经沙箱验证、人工审核后才可能写回；证据不足时不会为了弹审批而制造修改。

每次审查下方显示本次模型调用的输入、输出及总 token；顶部显示当前服务启动以来的累计值。统计直接使用兼容接口响应中的 `usage.prompt_tokens`、`usage.completion_tokens` 和 `usage.total_tokens`，部分兼容服务的 `input_tokens` / `output_tokens` 也可识别。接口未返回完整用量时会增加“未上报”次数，不会把未知 token 记为 0。用量暂存在服务内存中，重启 `hermes-web` 后累计值清零；具体费用请以模型服务商账单为准。

## Agent 运行日志

每条回答可展开「查看 Agent 运行日志」，按时间查看任务创建、模式选择、每次工具调用及剩余预算、取证结果摘要、结论收束、沙箱验证、人工审批和逐次 token 用量。模型若按协议给出 `reason`，页面会展示一句简短的决策说明；旧模型不返回时会明确标记为未提供。这里记录的是**模型自述与程序实际执行的可观察轨迹**，并不是模型不可见的内部思维链，不应把 `reason` 当成真实推理过程的逐字记录。

每个任务同步写入启动目录的 `.hermes/traces/<任务编号>.jsonl`，一行一条 JSON，包含 `seq`、`time`、`stage`、`event`、`summary`、`details`。例如：

```json
{"seq":4,"time":"2026-09-24T10:30:00.000+08:00","stage":"取证","event":"tool_result","summary":"read_file 完成","details":{"tool":"read_file","reason":"先检查入口处理逻辑","remaining_calls":8,"path":"src/main.py","requested_lines":[1,160],"outcome":"completed","line_count":78,"total_lines":78,"truncated":false}}
```

日志只保存文件路径、行数、数量、状态、用量等摘要；不会主动保存源码片段、工具原始输出、完整模型回复或 API key。模型提供的 `reason` 会截断并过滤常见密钥格式，但不能替代秘密扫描，敏感项目仍应限制本机日志访问。日志文件位于已被 Git 忽略的 `.hermes/` 中；若磁盘写入失败，页面仍会显示当前会话的内存日志与错误提示。可用 `tail -f .hermes/traces/<任务编号>.jsonl` 实时观察，用 `jq` 做统计；重启服务后可恢复已保存的会话，JSONL 也会保留。

若补丁未生成，查找同一任务的 `patch_retry`：`error_code` 区分无效 JSON、输出截断、请求了不允许的工具、目标未读、未读取目标行号、精确替换未命中等情况；`reply_chars` 仅记录回复长度，不保存原文。旧日志没有这些字段，因此无法事后准确判断旧任务的具体失败类型。

## Python 测试沙箱

启动 Docker Desktop 后，在 Hermes 项目目录构建一次镜像：

```bash
docker build -t hermes-sandbox:local sandbox
hermes-web
```

刷新页面，直接提问「审查项目并运行 tests 目录中的测试」。Hermes 会根据问题自动决定是否调用沙箱测试；页面可展开查看原始测试输出。

沙箱只复制源码白名单中的文件，排除隐藏文件、`.env`、凭据文件、依赖目录、符号链接和硬链接；这不是内容级秘密扫描，源码里硬编码的密钥仍需自行清除。快照最多 500 文件、单文件 256 KB、总计 20 MB。容器使用非 root 用户、禁网、只读根目录和源码挂载，测试在容器临时副本内执行；限制 1 CPU、512 MB 内存、64 进程、128 MB 临时空间、60 秒和 32 KB 输出。完成、超时或输出超限后均删除本次容器。

首版镜像提供 Python 3.11 与 pytest，不自动安装被审查项目的额外依赖。缺少依赖会展示实际错误，不能据此认定项目有 Bug。原项目不会因测试而修改；Docker socket 和 Hermes API key 不会传入容器。此方案适合本机项目测试，不作为公开多租户运行恶意代码的完整隔离平台。

开发者可运行真实隔离验证：`HERMES_SANDBOX_INTEGRATION=1 PYTHONPATH=src python -m unittest discover -s tests -p test_sandbox.py -v`。

## 修复 Agent 与人工审核

页面只需输入自然语言，例如「修复 main.py 的除零问题，保留现有行为并补充回归测试」。Hermes 先判断本次是代码审查还是修复，再按需要创建过滤快照、修改临时源码并在 Docker 中验证。默认静态查找项目中的 `test_*.py` / `*_test.py` 测试入口，不再要求手动创建 `tests/`。没有可运行测试时，自动进入仅允许修改测试文件的补充阶段，生成针对本次修改的回归测试。数据库调试脚本仅有测试命名但没有测试函数时，不作为默认入口。测试生成失败、依赖缺失或测试失败会如实展示，不能据此批准写回。

模型可以用 `create_file({path,content})` 新建 Python 源码和测试文件，用 `edit_file` 精确替换或按已读取行号修改已有文件，一次最多 5 个文件。行号替换要求读取版本与当前副本一致。所有创建和修改先发生在临时副本中；审批弹窗逐文件标注「新建」「修改」「测试文件」，显示业务代码和测试的全部差异。测试通过才启用「批准并写回」，批准后才在原项目创建目录/文件或修改文件，随后 Agent 继续核对。批准接口独立于模型工具，模型无法自行批准；拒绝不会写回。

当前没有删除或重命名工具，也不允许清空整个文件。绝对路径、`..`、隐藏目录、密钥文件和非 Python 写入均被拒绝；不跟随符号链接，不修改硬链接。新建使用不覆盖目标的原子发布操作，即便在审批后目标突然出现，也会保留用户文件并报告冲突。批准时重新检查源码快照的文件列表与内容哈希，项目有新改动就要求重新生成，避免应用过期方案。

写回前把原文件和审批记录保存在 Hermes 启动目录的 `.hermes/backups/<方案编号>/`，页面显示备份路径。`manifest.json` 区分新建和修改。普通写入失败会尝试回滚：恢复已有文件，仅移除本次新建且内容未被他人改动的文件；不递归删除目录。若进程中断或外部并发改动导致无法回滚，可根据备份与记录人工恢复。多文件写入并不是跨文件系统事务。待审批方案目前保存在内存中，服务重启后需要重新生成。

沙箱隔离的是项目执行；人工批准才授予原项目写入权限。运行生成测试仍使用 `hermes-sandbox:local` 镜像，保持禁网、只读挂载和 60 秒上限；镜像中只有 Python 与 pytest，不自动安装业务依赖。更新 `sandbox/runner.py` 后需重新执行 `docker build -t hermes-sandbox:local sandbox`。零测试或全部跳过不能作为通过。测试由模型生成或修改时也会纳入审批，测试通过只表示选定范围通过，不保证覆盖所有行为；这个本地实现也不宣称已具备与 Codex 相同的安全保证。

## 确定性演示模式

未配置模型时仍可运行可复现的规则引擎演示：

```bash
# 单次诊断：运行后输出一份报告并退出
hermes "legal-agent 最近很慢，帮我排查原因" --mode rules --scenario api_slow

# 交互模式：可以连续输入多个故障问题
hermes --interactive --mode rules --scenario api_slow
```

交互模式中输入故障描述即可诊断；输入 `exit` 或 `quit` 退出。每次提问都会创建独立事件编号，并分别保存报告和 trajectory，避免多个事故的证据混在一起。

默认演示场景稳定复现了一个可信的 AI 推理事故：

| 信号 | 证据 |
| --- | --- |
| 用户症状 | API 延迟：800 ms → 4200 ms |
| 健康检查 | HTTP 200，但 `latency_ms=4200` |
| GPU | 77,210 / 81,920 MB 显存，94% 利用率 |
| 日志 | 请求排队与 GPU 显存压力告警 |
| Git / 配置 | 最近发布将 `batch_size: 16 → 64` |

Hermes 会得出有依据的根因和最小回退方案，然后明确停在“等待用户批准”。它不会修改配置，也不会重启容器。

每次运行都会在 `artifacts/` 中产生：

- `*-report.md`：面向人的中文事件报告
- `*-trajectory.json`：工具调用、结果、状态转换、诊断与操作记录，可用于后续评测

可用 `hermes --list-tools` 查看工具白名单；`--scenario api_500` 可查看“证据不足时安全停止”的行为。

## Docker 故障实验环境

PRD 中的演示环境已落地为一个轻量 Docker Compose 服务。它不是生产环境模拟器，而是用于稳定复现 API 慢、API 500 和恢复正常三种情况；状态文件通过 volume 挂载到容器，注入故障不需要重建镜像。

```bash
# 终端 A：启动演示服务
docker compose -f demo/docker-compose.yml up --build

# 终端 B：注入慢接口故障
python demo/inject_fault.py --scenario api_slow

# 确认服务已变慢（约 4.2 秒返回）
curl -i http://localhost:8000/health

# 恢复正常状态
python demo/inject_fault.py --scenario normal
```

故障注入仅改写 `demo/runtime/state.json`，不会执行容器删除、重启、停止进程或任何宿主机变更命令。可用场景为 `normal`、`api_slow`、`api_500`。

Docker 环境启动后，可让 Hermes 读取真实的 HTTP 与 Docker 日志（其余主机采集项若不可用，会在报告中如实说明）：

```bash
hermes "legal-agent 为什么变慢了？" \
  --mode rules \
  --backend live \
  --service legal-agent \
  --container legal-agent \
  --health-url http://localhost:8000/health
```

## 本机只读采集

除了演示场景，还可以通过固定的、无 Shell 拼接的命令读取本机状态：

```bash
hermes "检查本机 legal-agent 是否正常" --mode rules --backend live --service legal-agent
```

本机模式只会尝试采集系统负载、NVIDIA GPU、Docker、HTTP 健康检查和 Git 差异。环境未安装 Docker、没有 NVIDIA GPU、服务不可访问等情况会如实写入报告，且诊断会因关键证据缺失停止；绝不会把失败伪装成成功。

> 本机模式仍然只有只读能力。`restart_service` 与 `edit_config` 只是已登记的危险工具，调用会在工具层被拒绝。

### 本机采集的前置条件

这些不是 `pip` 依赖，而是被诊断对象所在机器应具备的运行能力：

| 能力 | 是否必需 | 说明 |
| --- | --- | --- |
| HTTP 服务与正确的健康检查 URL | 基础诊断必需 | 例如 `http://localhost:8000/health`；`404` 是服务异常证据，不是 Python 安装问题。 |
| Docker Desktop / Docker daemon | 仅诊断容器时需要 | 启动 Docker Desktop 后，用 `docker ps` 确认可连接。 |
| NVIDIA 驱动与 `nvidia-smi` | 仅诊断 GPU 推理时需要 | Apple Silicon / 普通 Mac 没有 NVIDIA GPU，这是正常情况。 |
| 有至少一次提交的 Git 仓库 | 仅分析发布变更时需要 | 首次初始化、尚未提交的仓库没有可比较的历史版本。 |

`wps` 是桌面应用名称，不是 Hermes V0.1 支持的 HTTP / Docker 服务对象。若要诊断本机 WPS，应另行实现 macOS 应用进程、崩溃日志和性能采集适配器；它不应被当成 `http://wps:8000/health` 一类服务。

## 架构

```text
用户故障描述
    ↓
LLMSREAgent：模型选择下一项只读工具
    ↓
ControlledTools：程序校验工具与参数，不提供任意 Shell
    ↓
ScenarioBackend（可复现演示） / LiveReadOnlyBackend（本机只读）
    ↓
证据轨迹 → 模型假设 → 程序验证证据引用 → 报告
    ↓
修复计划（需要审批；当前不会执行）
```

工具边界就是安全边界。`system_metrics`、`gpu_metrics`、`docker_list`、`docker_logs`、`service_health`、`git_recent_changes`、`config_diff` 与 `git_code_review` 是只读工具。`restart_service`、`edit_config` 被定义为危险操作，并且在进入任何后端之前即被阻断。

## 安全设计

- 没有通用的 `run_shell` 工具。
- 每次只读观察及其失败都会被记录到 trajectory。
- 只有多条独立证据互相印证，才会给出高置信度根因。
- 缺少或冲突的证据会产生“未确定”报告，绝不编造结论。
- 当前版本没有任何修复执行路径。

### 代码审查是否需要沙箱？

需要分层处理：**只读差异审查**不需要运行代码，但仍应在只读工作区中进行，限制读取范围、返回长度，并把 Git diff / 日志视为不可信输入，防止提示注入。Hermes 的 `git_code_review` 正是这一层：仅调用禁用外部 diff 与分页器的受限 `git diff`，最多返回 20,000 字符，绝不执行仓库内容。

**运行测试、构建、复现故障或执行脚本**则必须进入独立沙箱：临时 worktree 或容器、无默认网络、无生产密钥、CPU / 内存 / 时长限制，并且需要用户明确授权。它与 SRE 修复执行器应是两个独立权限域。当前版本尚未提供这类执行沙箱，因此页面不会运行任何项目代码。
